# Задание 1. Безопасность входа

Здесь две вещи: схема, как управлять учётными записями (задание 1.1), и переход на PKCE (задание 1.2). Всё это живёт в одном стенде, запускается одной командой.

## Схема

Файл `BionicPRO_C4_account-management.drawio` (и картинка рядом). Я взял исходную C4-диаграмму BionicPRO и дорисовал то, что нужно для задачи. Светло-голубые блоки были в исходной схеме, тёмно-синие добавлены.

Идея такая:

- Браузер и мобильное приложение никогда не видят токены. Они общаются с BFF, а он выдаёт им только cookie сессии. Access и refresh токены BFF хранит у себя, в Redis, и сам обновляет их, когда они подходят к концу.
- Keycloak выступает посредником. Для каждой страны, где есть своё представительство, в нём заводится отдельный Identity Provider (OIDC, SAML или LDAP). Появилась новая страна, значит, добавляем ещё один провайдер, а приложение и BFF не трогаем.
- Персональные и медицинские данные остаются в локальной базе той страны, где живёт пользователь. Достать их можно только через Profile Service. В Keycloak лежит лишь идентификатор и ссылка на внешний аккаунт.

## Что из этого есть в коде

BFF сделан по-настоящему: это сервис `bff/` (FastAPI) с Redis. Он ведёт вход, хранит токены, ходит за отчётом в API. Так что «токены не доходят до фронтенда» не только нарисовано, но и работает: в браузере остаётся одна httpOnly-cookie, в `localStorage` и `document.cookie` пусто.

А вот Profile Service, локальные базы стран и подключение реальных внешних IdP только нарисованы. Подключать тут нечего: настоящих внешних систем у нас нет.

## PKCE

Раньше фронтенд сам получал код и менял его на токен. Теперь вход идёт через PKCE:

- BFF при каждом входе придумывает случайный `code_verifier`, отправляет в Keycloak его хеш (`code_challenge`, метод S256), а при обмене кода на токен показывает сам `code_verifier`. Перехватить код на редиректе бесполезно: без verifier его не обменять.
- В Keycloak (`keycloak/realm-export.json`) у клиента `reports-bff` включено требование `pkce.code.challenge.method = S256`, то же самое стоит у клиента `reports-frontend`. Прямой вход по логину и паролю и неявный поток выключены. Запрос без `code_challenge` Keycloak отклоняет.

Клиент `reports-frontend` остался в realm как был, но самим приложением больше не используется: теперь вход выполняет BFF.

## Как проверить

Поднять всё:

```bash
docker compose up -d --build
```

Потом прогнать скрипт, который сам проходит вход через BFF и проверяет cookie, отчёт и выход:

```bash
python Task1/check_bff.py
```

Или руками: открыть http://localhost:3000, нажать Login, войти как `prothetic1` / `prothetic123`. В адресной строке Keycloak при этом будет видно `code_challenge_method=S256`.

Секрет клиента `reports-bff` и тестовые пароли лежат в репозитории открыто, потому что это учебный стенд. Для настоящего окружения их надо выносить в переменные окружения.
